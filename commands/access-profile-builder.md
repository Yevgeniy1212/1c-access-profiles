# access-profile-builder

Создание профиля на основе существующего. Самый безопасный путь для нетехнического
пользователя: не нужно вручную подбирать роли.

## Шаги

1. Проверить `.roles-access.yaml`. Нет — `/access-init`, остановиться.
2. Выяснить через AskQuestion:
   - имя нового профиля (как оно должно выглядеть в 1С);
   - профиль-образец (предложить варианты из `/access-profiles-list`);
   - комментарий (необязательно).
3. **Сначала показать план** (без записи):

   ```
   python .cursor/1c-access-profiles/scripts/profile_save.py --name "<новый>" --from "<образец>" --comment "<комментарий>"
   ```

4. Показать пользователю, что будет скопировано, и **дождаться явного согласия**.
5. Только после согласия выполнить с флагом записи:

   ```
   python .cursor/1c-access-profiles/scripts/profile_save.py --name "<новый>" --from "<образец>" --comment "<комментарий>" --apply
   ```

6. Проверить результат: `/access-profiles-list` и `/access-profile-analyze <новый>`.
7. Показать сводку: имя, число ролей, совпадает ли с образцом.

## Если нужно не копирование, а изменение состава

Скопируйте профиль, затем попросите внести правки:
1. `/access-profile-builder` — создаёт копию;
2. далее агент правит состав через `profile_save.py` (нужно расширение сценария)
   либо через `execute_code` по согласованию.

Не редактируйте поставляемые профили (`СВОЙ = нет`) — правки исчезнут при обновлении.

## Требование к базе

Для записи в 1С в форме MCP Toolkit должен быть включён флажок
**«Записать»** в блоке «Автоматически разрешать операции». Иначе платформа покажет
окно подтверждения прямо в 1С — пользователь должен нажать «Да».

## Запреты

- Записывать в базу без явного согласия пользователя.
- Перезаписывать существующий профиль молча — при совпадении имени скрипт
  предупреждает, что роли будут заменены; это нужно подтвердить отдельно.
- Создавать профиль без роли запуска — предупредить пользователя.

## Дальше
