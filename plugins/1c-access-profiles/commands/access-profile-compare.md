# access-profile-compare

Сравнение двух профилей. Отвечает на вопросы: «чем отличается Склад от Менеджера
по закупкам», «что лишнего в этом профиле», «можно ли объединить». Только чтение.

## Шаги

1. Проверить `.roles-access.yaml`. Нет — `/access-init`, остановиться.
2. Спросить у пользователя названия двух профилей (AskQuestion с вариантами
   из `/access-profiles-list`, если список невелик).
3. Выполнить:

   ```
   python .cursor/1c-access-profiles/scripts/profile_compare.py --left "<профиль 1>" --right "<профиль 2>"
   ```

   С разницей по объектам: добавьте `--objects`.

4. Показать результат и объяснить:
   - общие роли — база, на которой профили совпадают;
   - «только в первом» / «только во втором» — чем отличаются;
   - с `--objects`: объекты, до которых есть доступ у одного и нет у другого.

## Как объяснять пользователю

- Разница в ролях далеко не всегда означает разницу в доступе: одна «широкая» роль
  может перекрывать несколько «узких». Поэтому при спорных случаях смотрите блок
  объектов (`--objects`), а не только список ролей.
- Если профили отличаются двумя-тремя ролями — возможно, стоит завести один общий
  профиль и разницу вынести в отдельный. Это уменьшает число сущностей.

## Запреты

- Не изменять данные.
- Не предлагать «удалить лишние роли», не показав пользователю конкретные объекты,
  которые от этого пропадут.
