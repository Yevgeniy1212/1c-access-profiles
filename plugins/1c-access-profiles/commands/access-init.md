# access-init

Настройка подключения к базе 1С. Выполняется один раз на проект.

## Когда применять

Первый запуск плагина в новом проекте, либо смена базы (другой адрес MCP Toolkit).

## Шаги

1. Определить адрес сервера:
   - передан аргументом команды — использовать его;
   - иначе проверить `.cursor/mcp.json` на наличие сервера с `url`;
   - иначе спросить у пользователя (AskQuestion): «Укажите адрес MCP Toolkit,
     например `http://10.20.0.100:6004`».
2. Выполнить:

   ```
   python .cursor/1c-access-profiles/scripts/init_access.py --url <адрес>
   ```

   Скрипт сам: проверит `/health`, прочитает имя и версию конфигурации, версию БСП,
   проверит роль-мастер RLS и роли-эталоны, создаст `.roles-access.yaml` и `workdir`.

3. Показать пользователю результат из вывода скрипта:
   - конфигурация, версия, БСП;
   - сколько ролей-эталонов найдено (если есть отсутствующие — перечислить);
   - путь к созданному файлу.

## Если скрипт сообщает об ошибке

| Сообщение | Что делать |
|---|---|
| «нет связи с MCP Toolkit» | Проверить, что обработка MCP Toolkit открыта в 1С и сервер запущен; сверить адрес и порт |
| «сервер не отвечает на /health» | То же; проверить доступность адреса (`ping`, файрвол) |
| «роль-мастер не найдена» | База не на БСП либо другая версия библиотеки — плагин не подойдёт |
| «HTTP 401» | В форме MCP Toolkit задан токен — его нужно вписать в `.cursor/mcp.json` |

## Запреты

- Не придумывать адрес сервера: только из аргумента, `mcp.json` или ответа пользователя.
- Не перезаписывать существующий `.roles-access.yaml` без подтверждения.
