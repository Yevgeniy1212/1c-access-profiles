# access-profile-analyze

Главная команда плагина: показывает, к каким объектам базы профиль даёт доступ
и на каком уровне. Только чтение.

## Шаги

1. Проверить `.roles-access.yaml`. Нет — `/access-init`, остановиться.
2. Имя профиля не передано — спросить через AskQuestion, предварительно показав
   список (`/access-profiles-list`).
3. Выполнить:

   ```
   python .cursor/1c-access-profiles/scripts/profile_analyze.py --profile "<имя>" --out "workdir/reports/<имя>-<дата>.txt"
   ```

4. Показать сводку: сколько объектов, сколько «чтение» / «изменение»,
   распределение по видам.
5. Если пользователь просит подробности — показать список объектов по нужному виду.

## Как объяснять пользователю

- **изменение** — можно создавать и править;
- **чтение** — только смотреть;
- объект отсутствует в списке — доступа нет;
- «Присоединённые файлы» — служебные объекты: они идут вместе со своим владельцем,
  отдельно их обсуждать не нужно.

## Что важно проверить глазами

1. Попадают ли в профиль **объекты, которых там быть не должно** (лишние права).
2. Не потеряны ли объекты, которые пользователь ожидает увидеть.
3. Для профилей с ограничением по организации — учтено ли, что RLS-фильтрация
   сужает видимость поверх этих прав.

## Запреты

- Не изменять данные.
- Не утверждать «доступа нет» на основании только списка ролей: проверять
  фактические права (это и делает скрипт).
