# access-profiles-list

Обзор профилей доступа. Ничего не меняет — только чтение.

## Шаги

1. Проверить наличие `.roles-access.yaml` в корне проекта. Нет — предложить
   `/access-init`, остановиться.
2. Выполнить:

   ```
   python .cursor/1c-access-profiles/scripts/profiles_list.py
   ```

   С маской: `python .cursor/1c-access-profiles/scripts/profiles_list.py --mask МТО`
   Состав конкретного: `python .cursor/1c-access-profiles/scripts/profiles_list.py --details "Склад"`

3. Показать таблицу как есть. Пояснить пользователю смысл колонок при первом показе:
   - `СВОЙ = да` — профиль создан в этой организации (не поставляемый 1С);
   - `СВОЙ = нет` — поставляемый профиль от вендора, его правки «слетают» при обновлении;
   - `РОЛЕЙ` — сколько ролей входит в профиль, `0` — пустой профиль.

## Что сказать пользователю

- Профилей с `РОЛЕЙ = 0` быть не должно: такой профиль ничего не даёт, а пользователь
  в нём останется без доступа.
- Для повседневной работы используйте `СВОЙ = да`.

## Запреты

- Не изменять данные. Команда только читает.
