# access-profile-explain

Отвечает на вопрос «почему у этого профиля есть вот этот документ и какая роль его притащила».
Только чтение. Роли не изменяются.

## Шаги

1. Проверить `.roles-access.yaml`. Нет — `/access-init`, остановиться.
2. Нужны имя профиля и объект. Объект можно передать синонимом (`ГТД по импорту`) или именем метаданных.
3. Выполнить:

   ```
   python .cursor/1c-access-profiles/scripts/profile_explain.py --profile "<профиль>" --object "<объект>"
   ```

4. Показать роль, уровень (чтение или изменение) и сколько документов открывает эта роль.

## Как объяснять пользователю

- Объект есть у профиля, потому что его даёт конкретная роль из состава профиля.
- Большое число документов у одной роли значит, что роль широкая. Профиль получает всё, что в ней есть, а не один объект.
- Чужую и типовую роль не править и не вырезать из неё отдельные объекты.
- Если объекта нет в матрице доступа, эту роль в профиль не включать.
- Узкую роль вместо широкой делает разработчик в конфигураторе. Плагин роль не создаёт.

## Запреты

- Не изменять роли и профиль.
- Не говорить «убери объект из роли», если роль чужая или типовая.
- Не утверждать, что доступа нет, пока скрипт не проверил `ПравоДоступа`.
