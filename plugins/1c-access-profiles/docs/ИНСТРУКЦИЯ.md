# Инструкция: работа с профилями доступа в 1С

Для тех, кто не занимается разработкой. Ничего программировать не нужно —
достаточно писать в чат Cursor обычными словами.

---

## Шаг 1. Что вообще происходит

В 1С права настраиваются на трёх уровнях:

| Уровень | Что это | Простой пример |
|---|---|---|
| **Роль** | набор прав на объекты программы | «Чтение номенклатуры» |
| **Профиль** | набор ролей | «Кладовщик: справочники + документы» |
| **Группа доступа** | профиль, выданный людям | «Кладовщики: Иванов, Петров» |

Чтобы человек мог работать в программе, ему нужна группа доступа. Группа ссылается
на профиль. Профиль состоит из ролей.

Этот плагин помогает разобраться в профилях: что в них лежит и что это даёт людям.

---

## Шаг 2. Подключение — один раз

### Узнать адрес

Адрес вам сообщает администратор базы. Выглядит так:

```
http://10.20.0.100:6004
```

Это адрес обработки **MCP Toolkit**, открытой в 1С. Важно: обработка должна быть
открыта, а сервер — запущен. Если окно 1С с обработкой закроют, плагин перестанет
работать.

### Настроить

В чате Cursor напишите:

```
/access-init http://10.20.0.100:6004
```

Подставьте свой адрес. Плагин проверит связь и покажет примерно такое:

```
Адрес сервера: http://10.20.0.100:6004
Сервер отвечает: healthy (режим native)

База данных:
  Конфигурация : Бухгалтерия для Казахстана, редакция 3.0 3.0.69.1
  Совместимость: Version8_3_21
  БСП          : 3.1.9.261

Роль-мастер RLS: ИзменениеУчастниковГруппДоступа — найдена
Роли-эталоны: найдено 6 из 6

Готово.
```

Если увидели «Роли-эталоны: найдено 5 из 6» — не страшно, плагин просто будет
считать эту функцию без образца.

## Шаг 3. Посмотреть, какие профили есть

```
/access-profiles-list
```

Вы увидите таблицу:

```
ПРОФИЛЬ                    РОЛЕЙ  СВОЙ  КОММЕНТАРИЙ
-----------------------------------------------------
Бухгалтер                  130    нет
Администратор модуля МТО   57     да
Склад                      100    да
```

**Как читать:**

- **РОЛЕЙ** — сколько ролей внутри профиля. Чем больше, тем шире доступ.
- **СВОЙ = да** — профиль сделан в вашей организации.
- **СВОЙ = нет** — стандартный профиль от 1С. Его менять бессмысленно: при
  обновлении программы он вернётся к исходному виду.
- **РОЛЕЙ = 0** — пустой профиль. Человек с таким ничего не увидит.

Если профилей много, найдите нужные по фрагменту названия:

```
/access-profiles-list --mask Склад
```

## Шаг 4. Понять, что даёт профиль

```
/access-profile-analyze Склад
```

Плагин покажет:

```
Объектов с доступом: 122
  изменение: 86
  чтение: 45

Справочники (51):
  [изм] Номенклатура
  [чт ] Организации
  ...
```

**Как читать:**

- **[изм]** — можно создавать и редактировать;
- **[чт ]** — можно только смотреть;
- объекта в списке нет — доступа к нему нет вообще.

### Что означает «Присоединённые файлы»

Такие строки, как «Присоединённые файлы (Номенклатура)», — служебные. Они
появляются автоматически вместе с основным объектом. Отдельно их настраивать не нужно.

## Шаг 5. Сравнить два профиля

Частый вопрос: «почему кладовщик видит то же, что менеджер?» или «чем отличается
старый профиль от нового?»

```
/access-profile-compare --left "Склад" --right "Менеджер по закупкам"
```

Если нужны не только роли, но и объекты:

```
/access-profile-compare --left "Склад" --right "Менеджер по закупкам" --objects
```

**Как читать:**

- **Общих ролей: 52** — столько совпадает;
- **Только в «Склад»** — что есть у одного, но нет у другого.

Одинаковые роли ещё не значат одинаковые права: одна широкая роль может заменять
несколько узких. Если важна точность — смотрите блок объектов (`--objects`).

## Шаг 6. Проверить все профили на проблемы

```
/access-profile-check --all
```

Плагин найдёт:

| Что нашёл | Что это значит |
|---|---|
| `EMPTY_PROFILE` | профиль без ролей — человек с ним ничего не увидит |
| `ROLE_MISSING` | в профиле роль, которой в программе больше нет (обычно после обновления) |
| `NO_LAUNCH_ROLE` | нет роли запуска — человек не сможет войти в программу |
| `DUPLICATE_ROLE` | роль включена дважды — не страшно, но грязно |

После обновления конфигурации полезно запускать эту проверку — она покажет
профили, которые «сломались».

## Шаг 7. Создать новый профиль по образцу

Например, нужен профиль для нового отдела, похожий на существующий.

```
/access-profile-builder
```

Плагин спросит:

1. Название нового профиля — например «Кладовщик участка».
2. Профиль-образец — например «Склад».
3. Комментарий — не обязательно.

**Сначала ничего не запишется.** Плагин покажет план:

```
Профиль-образец «Склад»: ролей 100
Профиль «Кладовщик участка» будет создан.

Что будет скопировано:
  - состав ролей
  - виды доступа (ограничения RLS)
  - значения доступа
  - назначение (типы пользователей)

Режим проверки: в базу ничего не записано.
```

Проверьте, что всё верно, и подтвердите — только после этого плагин запишет профиль.

### Про окно подтверждения в 1С

При записи в 1С может появиться окно «Разрешить выполнение опасной операции?».
Нажмите **Да**. Это стандартная защита платформы.

Чтобы окна не было, администратор включает в форме MCP Toolkit флажок
**«Записать»**. Это его решение, не ваше.

## Шаг 8. Что делать дальше с новым профилем

Профиль сам по себе людей не касается — он только описывает набор прав.
Чтобы выдать доступ людям:

1. В 1С откройте **Администрирование → Настройки пользователей и прав**.
2. Создайте **группу доступа** и укажите в ней новый профиль.
3. Добавьте в группу пользователей.

Плагин этот шаг намеренно не делает: назначение доступов людям — решение
ответственного, а не автоматики.

---

## Шаг 9. Ограничения по организациям (RLS)

В 1С можно ограничить видимость: например, сотрудник видит только документы своей
организации. Это называется **ограничение на уровне записей**.

Плагин показывает, какие виды ограничений у профиля есть:

```
Виды доступа:
  Организации (ограничены)
  Склады (все разрешены)
```

«Ограничены» означает, что видны только явно разрешённые значения.
«Все разрешены» — видно всё.

**Чего плагин не может:** проверить, что ограничение действительно срабатывает.
Причина — платформа не отдаёт сами тексты ограничений через MCP. Если у профиля
несколько ролей на один и тот же объект и хоть одна без ограничения, ограничение
не сработает. Такую проверку делает разработчик в Конфигураторе.

## Частые вопросы

**Профиль показывает объект, а сотрудник его не видит. Почему?**
Ограничение по организации может сузить видимость. Плюс сотрудник может состоять
в нескольких группах — права складываются.

**Профиль не показывает объект, а доступ есть. Почему?**
Скорее всего, доступ даёт другая группа доступа пользователя, а не эта.

**Можно ли поправить профиль, а не создавать копию?**
Можно, но плагин этого не делает специально: правка существующего профиля сразу
меняет доступ живым людям. Безопаснее скопировать, проверить и переключить группы.

**Почему «СВОЙ = нет» менять нельзя?**
Это профиль от поставщика. При обновлении программы файлы профиля перезапишутся,
и ваши правки исчезнут.

**Что за «роль-мастер RLS»?**
Служебная роль, из которой берутся образцы ограничений. Её наличие означает, что
конфигурация построена на БСП и плагин с ней совместим.

## Если что-то сломалось

**«Нет связи с MCP Toolkit»**

1. Найдите на рабочем столе окно 1С с обработкой **MCP Toolkit**.
2. Убедитесь, что статус — «Сервер запущен».
3. Если окно закрыто — откройте обработку заново и нажмите «Запустить сервер».
4. Повторите команду.

**«HTTP 401»**

В форме MCP Toolkit задан токен доступа. Администратор должен либо очистить поле
«Токен доступа», либо вписать этот токен в настройки подключения плагина.

**«Роль-мастер не найдена»**

Конфигурация не на БСП либо очень старая версия библиотеки. Плагин не подойдёт.

**Команда выдаёт странные названия объектов**

Скорее всего, обновилась конфигурация и синонимы ролей изменились.
Запустите `/access-init` заново.
