# 1C Access Profiles

Плагин Cursor для работы с **профилями групп доступа** в конфигурациях 1С на БСП.

Отвечает на вопросы, которые обычно требуют ручного разбора в Конфигураторе:

- что на самом деле даёт профиль — к каким объектам и с каким уровнем доступа;
- чем один профиль отличается от другого;
- что не так с профилем — пустой, битые роли, нет роли запуска;
- как собрать новый профиль, не подбирая роли вручную.

Роли **не создаются и не изменяются** — плагин работает с теми, что уже есть в базе.

---

## Для чего это нужно

В 1С права выдаются так: **роль** даёт права на объекты, **профиль** объединяет роли,
**группа доступа** привязывает профиль к пользователям. Разобраться, что реально
видит бухгалтер или кладовщик, можно только пройдя всю цепочку.

Плагин проходит её за вас и показывает результат списком объектов.

---

## Как это работает с точки зрения пользователя

Один раз указываете адрес базы — дальше только вопросы и ответы.

1. Пишете: `/access-init http://10.20.0.100:6004`
2. Плагин проверяет связь, определяет конфигурацию и сохраняет настройки.
3. Дальше работаете командами из списка ниже.

---

## Требования

| Что | Зачем |
|---|---|
| **MCP Toolkit** в открытой базе 1С, сервер запущен | канал связи с 1С |
| Адрес сервера (например `http://10.20.0.100:6004`) | куда подключаться |
| Права администратора в базе | без них `ПравоДоступа` вернёт неверный результат |
| Python 3.9+ | скрипты плагина, только стандартная библиотека |

Проверить, что сервер жив:

```
http://10.20.0.100:6004/health
```

Ответ должен быть `{"status":"healthy", ...}`.

---

## Установка

Плагин ставится из Cursor Marketplace (раздел **Customize → MCPs/Plugins**)
либо кладётся в `~/.cursor/plugins/local/1c-access-profiles`.
После установки — перезагрузить окно Cursor.

---

## Настройка подключения

```
/access-init http://10.20.0.100:6004
```

Создаётся файл `.roles-access.yaml` в корне проекта. Его можно поправить руками —
там нет ничего, кроме адреса, имени конфигурации и ролей-эталонов.

Если адрес уже прописан в `.cursor/mcp.json`, аргумент можно не указывать.

---

## Команды

| Команда | Что спросить у плагина |
|---|---|
| `/access-init` | «Подключи меня к базе» |
| `/access-profiles-list` | «Какие профили есть в базе?» |
| `/access-profile-show <имя>` | «Что входит в этот профиль?» |
| `/access-profile-analyze <имя>` | «К каким объектам даёт доступ этот профиль?» |
| `/access-profile-explain` | «Какая роль даёт этот объект?» |
| `/access-profile-compare` | «Чем отличаются два профиля?» |
| `/access-profile-check` | «Что не так с профилями?» |
| `/access-profile-builder` | «Сделай новый профиль по образцу» |

### Примеры

**Посмотреть профили:**

```
/access-profiles-list
```

**Понять, что видит кладовщик:**

```
/access-profile-analyze Склад
```

Вывод: сколько объектов, что можно менять, что только смотреть.

**Найти, какая роль принесла лишний объект:**

```
/access-profile-explain --profile "Инициатор" --object "ГТД по импорту"
```

Плагин напишет имя роли и сколько документов эта роль открывает. Чужую роль не изменяют: если объекта нет в матрице, роль не включают в профиль.

**Сравнить два похожих профиля:**

```
/access-profile-compare --left "Склад" --right "Менеджер по закупкам" --objects
```

**Проверить все профили разом:**

```
/access-profile-check --all
```

## Что плагин НЕ делает

| Не делает | Почему |
|---|---|
| Не создаёт и не меняет роли | это задача разработчика в Конфигураторе |
| Не меняет конфигурацию | только работа с данными базы |
| Не назначает пользователей в группы | это администратор, осознанное решение |
| Не удаляет профили | удаление необратимо, оставлено человеку |
| Не проверяет ограничения RLS автоматически | платформа не отдаёт тексты ограничений через MCP |

---

## Про ограничения доступа (RLS)

В 1С можно ограничить видимость данных: например, бухгалтер видит только свою
организацию. Это задаётся в ролях и профилях, но **свойства ограничений недоступны
через MCP** — платформа не отдаёт их в рантайме.

Плагин показывает:
- какие виды доступа у профиля (Организации, Склады и т. д.);
- ограничены они или «все разрешены».

Полную проверку «ограничение обходится другой ролью профиля» нужно делать вручную
в Конфигураторе. Команда `/access-profile-check` прямо об этом предупреждает.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| «нет связи с MCP Toolkit» | открыть обработку MCP Toolkit в 1С, нажать «Запустить сервер» |
| «сервер не отвечает на /health» | проверить адрес и порт, доступность по сети |
| «HTTP 401» | в форме задан токен — вписать его в `.cursor/mcp.json` |
| «роль-мастер не найдена» | конфигурация не на БСП, плагин не подойдёт |
| «не удалось сопоставить роли» | после обновления конфигурации синоним роли изменился — нужен `/access-init` заново |

---

## Ограничения и известные особенности

1. **Нужны права администратора.** Без них проверка прав даёт неверный результат.
2. **Поставляемые профили** (`СВОЙ = нет` в списке) правятся только вендором;
   локальные изменения исчезнут при обновлении.
3. **Роли запуска** (`ЗапускТонкогоКлиента` и подобные) обязательны: без них
   пользователь не войдёт в программу, даже имея все права на объекты.
4. **Пустые профили** ничего не дают — их лучше удалять или наполнять.
